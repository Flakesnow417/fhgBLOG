## 【第三章】动手改（本章是核心）

---------- 3.1 先看懂文件的"骨架" ----------

  打开文件后，你会看到一堆英文和中文混在一起。别慌，我们只看"骨架"。

  从上往下，文件大致长这样：

      (开头是一大段灰色说明，用 /* 和 */ 包起来，是注释，不用管)

      export const CORRIDOR_ARTWORKS = [
        {
          id: 'about',
          title: '关于我',
          caption: '一个喜欢把界面当成纸上草稿来画的人',
          side: WALL_SIDE.LEFT,
          motif: 2,
          seed: 101,
          accent: '#c8532f',
          detail: {
            lead: '把复杂的东西拆开、画在纸上...',
            blocks: [
              {
                heading: '我是谁',
                items: [
                  '前端工程师，主攻三维交互与可视化方向',
                  '习惯先用草图推敲结构，再写实现',
                  ...
                ],
              },
              ...
            ],
          },
        },
        { ← 第二幅画（技能）从这里开始
          ...
        },
        ...
      ]

  关键就是这个：

      【[ ] 方括号里面的，是"一幅一幅的画"。】
      【{ } 大括号里面的，是"一幅画的信息"。】

  6 幅画 = 6 个大括号，用逗号隔开，最后一个不用逗号。

---------- 3.2 每一幅画的"零件"说明书 ----------

  一幅画长这样（下面我加了行内说明）：

      {
        id: 'about',                     ← 身份证号，见下方 A
        title: '关于我',                  ← 弹窗的大标题，见下方 B
        caption: '...',                  ← 画框下面那行小字，见下方 C
        side: WALL_SIDE.LEFT,            ← 挂左墙还是右墙，见下方 D
        motif: 2,                        ← 画框里画什么形状（程序生成），见 E
        seed: 101,                       ← 随机数种子，见下方 F
        accent: '#c8532f',               ← 强调色，见下方 G
        detail: { ... },                 ← 弹窗里的正文，见下方 H
      },

  ┌────────────────────────────────────────────────────────────────────┐
  │ A. id —— 身份证号                                                  │
  └────────────────────────────────────────────────────────────────────┘

      作用：程序内部用来区分"这是哪一幅"。
      要求：
        · 必须是英文，不能有空格
        · 每幅画的 id 【必须不一样】
      建议：【不要改它】。改了对功能没影响，但也没好处。
      比喻：就像学号。你改名字没关系，但没必要去改学号。

  ┌────────────────────────────────────────────────────────────────────┐
  │ B. title —— 弹窗的大标题                                            │
  └────────────────────────────────────────────────────────────────────┘

      作用：点开画框后，弹窗最上面那个大字。
      现在的内容：'关于我' / '技能' / '项目作品' ...

      怎么改：

          改前：  title: '关于我',
          改后：  title: '张三',

      ⚠️ 四条规矩（非常重要，违反任何一条文件就坏）：

        1. 【文字必须用单引号 ' ' 包起来】
           对的：  title: '张三',
           错的：  title: 张三,          ← 没有引号

        2. 【单引号必须是英文的，不能用中文的 ' '】
           对的：  title: '张三',        ← 英文单引号
           错的：  title: '张三',        ← 中文引号，会报错

           ⚠️ 这是新手第一大坑！
           中文输入法下按引号键，出来的就是中文引号。
           输入引号时【先把输入法切到英文】（按 Shift 或 Ctrl+空格）。

        3. 【末尾那个逗号不能少】
           对的：  title: '张三',
           错的：  title: '张三'         ← 少了逗号

        4. 【引号里面的内容不要写换行】
           想写长的，就写成一行。

      💡 小技巧：引号里面可以放中文、英文、数字、空格、符号。
         只要不出现单引号本身，随便写。
         如果真的需要写一个单引号，写成 \' （反斜杠加单引号）。

  ┌────────────────────────────────────────────────────────────────────┐
  │ C. caption —— 画框下的小字                                          │
  └────────────────────────────────────────────────────────────────────┘

      作用：走廊里挂在画框下方的那一行小字，相当于"副标题"。
      现在的内容：'一个喜欢把界面当成纸上草稿来画的人'

      怎么改：和 title 完全一样，规则也完全一样。

          改前：  caption: '一个喜欢把界面当成纸上草稿来画的人',
          改后：  caption: '前端工程师 / 喜欢做可视化',

      💡 建议写短一点（20 字以内）。太长了画框下面会显得挤。
         拿不准就写一个"岗位 + 一个特点"。

  ┌────────────────────────────────────────────────────────────────────┐
  │ D. side —— 挂在哪面墙上                                            │
  └────────────────────────────────────────────────────────────────────┘

      作用：决定这幅画挂在走廊的左墙还是右墙。

      能填的值【只有两个】：

          WALL_SIDE.LEFT      ← 左墙
          WALL_SIDE.RIGHT     ← 右墙

      怎么安排比较好看：
        现在作者是 左、右、左、右、左、右 这样交替的。
        建议保持交替，走起来左右都有东西看，不会一边空着。

      ⚠️ 这一项【不会报错，但会悄悄出错】，所以特别说明一下：

        如果你写成  side: 'left',     ← 少写了 WALL_SIDE. 前缀

        程序【不会崩】，页面也照常显示。但是这幅画会被挂到——
        等等，'left' 恰好和程序内部认的那个值一样，所以它【碰巧能用】。

        真正危险的是写成别的：

            side: 'Left',      ← 首字母大写   → 会被当成"右墙"
            side: '左',        ← 中文         → 会被当成"右墙"
            side: 'top',       ← 瞎写         → 会被当成"右墙"

        原因（不用记，知道有这么回事就行）：
        程序里判断墙面的写法是
            if (side === 'left') { 挂左墙 } else { 挂右墙 }
        所以【只要不等于 'left'，就一律按右墙处理】。
        写错了既不报错、也不提示，只是默默地挂错地方。

        💡 结论：【老老实实写 WALL_SIDE.LEFT / WALL_SIDE.RIGHT。】
           它看起来啰嗦，但它是"官方名字"，
           以后程序内部的值改成别的，它也不会失效。

  ┌────────────────────────────────────────────────────────────────────┐
  │ E. motif —— 画框里画什么形状（程序生成的占位图）                     │
  └────────────────────────────────────────────────────────────────────┘

      作用：画框里那张"素描"是程序画出来的。这个数字决定画什么。

      能填的值只有 4 个：

          0  →  立方体（几何体）
          1  →  球体（带一条地平线）
          2  →  石膏头像（古典雕塑那种）
          3  →  一只手

      现在作者填的是：2, 0, 3, 1, 0, 3

      怎么改：填 0-3 之间的整数就行，随便排。
      💡 建议：相邻两幅不要用同一个数，看起来丰富一些。

      ⚠️ 填了 4 或者 99 会怎样？——【不会报错】，
         程序里有个兜底，超出范围就按 0（立方体）处理。
         所以这是个"随便填也不会崩"的选项。

      📌 注意：这是"程序画的假图"。
         如果你想换成真实的图片（比如你自己的设计稿、水墨画、油画），
         那是另一件事，不在这里改。

  ┌────────────────────────────────────────────────────────────────────┐
  │ F. seed —— 随机数种子                                              │
  └────────────────────────────────────────────────────────────────────┘

      作用：程序画那张素描时，要加很多"随机的铅笔颗粒和笔触"。
      这个数字就是"随机"的起点。

      · 数字一样 → 每次画出来【完全一样】
      · 数字不一样 → 颗粒和笔触的分布就不一样

      怎么改：随便填个整数，比如 101、202、303……
      💡 如果觉得某幅画的颗粒太乱或者太干净，
         就改这个数字试试，多试几个，找顺眼的。
         【改它是零风险的】，不会出错，只会变化。

  ┌────────────────────────────────────────────────────────────────────┐
  │ G. accent —— 强调色                                                │
  └────────────────────────────────────────────────────────────────────┘

      作用：鼠标指上去、画从黑白变成彩色时，主要的那个颜色。

      格式：【井号 + 6 位字母或数字】，必须用【单引号】包起来。

          对的：  accent: '#c8532f',      ← 红棕色
          对的：  accent: '#2f6f8f',      ← 灰蓝色
          错的：  accent: 'c8532f',       ← 少了 #
          错的：  accent: '红色',          ← 不能用中文颜色名
          错的：  accent: #c8532f,        ← 少了引号

      现在文件里用到的 6 个颜色（可以直接抄）：

          '#c8532f'   红棕（暖）
          '#2f6f8f'   灰蓝（冷）
          '#7a5c9e'   紫
          '#2f8f6f'   青绿
          '#a8802f'   土黄
          '#c8532f'   红棕（和第一个一样）

      想换颜色但不知道代码？
        · 打开 https://www.colorhexa.com
        · 上面有个色块可以点，选你喜欢的颜色
        · 页面会显示 "Hex: #xxxxxx"，把那个 #xxxxxx 抄过来就行
        · 或者直接搜"在线取色器"

  ┌────────────────────────────────────────────────────────────────────┐
  │ H. detail —— 弹窗里的正文（内容最多，但结构很整齐）                  │
  └────────────────────────────────────────────────────────────────────┘

      这是整幅画里文字最多的地方。它长这样：

          detail: {
            lead: '一句话开场白',
            blocks: [
              {
                heading: '小标题一',
                items: [
                  '第一条内容',
                  '第二条内容',
                ],
              },
              {
                heading: '小标题二',
                items: [
                  '第一条内容',
                ],
              },
            ],
          },

      拆开看三个零件：

        ┌──────────────────────────────────────────────────┐
        │ lead —— 开场白（斜体、在弹窗最上面）              │
        └──────────────────────────────────────────────────┘

            就是一句话，用单引号包起来，末尾加逗号。

                lead: '不追求名词的堆叠，只说真正能独立交付的部分。',

        ┌──────────────────────────────────────────────────┐
        │ blocks —— 一组一组的内容（一个 {} 就是一组）      │
        └──────────────────────────────────────────────────┘

            每一组里面有两个东西：

              heading: 这一组的标题（用单引号）
              items:   这一组的内容（用方括号 [ ]，里面一行一条）

            想加一组？照着复制一个 { ... }, 块，粘在下一行就行。
            想删一组？把整个 { ... }, 删掉（注意别漏删逗号）。

        ┌──────────────────────────────────────────────────┐
        │ items —— 一条一条的内容                           │
        └──────────────────────────────────────────────────┘

            【最简单】的写法：直接写字符串。

                items: [
                  '课程重心：数据结构、图形学基础、人机交互',
                  '毕业设计做的是一个可视化的算法演示系统',
                ],

                → 弹窗里显示成两行带小横杠的文字。

            【进阶】写法：写成"标签 + 值"，弹窗会自动对齐成两列。

                items: [
                  { label: '邮箱',   value: 'hello@example.com' },
                  { label: 'GitHub', value: 'github.com/example' },
                ],

                → 弹窗里显示成：
                     邮箱        hello@example.com
                     GitHub      github.com/example

                ⚠️ label 和 value 都要用单引号，中间用英文冒号，末尾逗号。

            💡 什么时候用哪种？
               · 联系方式这种"名字 + 号"的 → 用进阶写法，好看
               · 其他描述性的 → 用简单写法就行

---------- 3.3 三条"绝对不能违反"的铁律 ----------

  ┌────────────────────────────────────────────────────────────────────┐
  │ 铁律一：所有标点必须是【英文半角】                                 │
  └────────────────────────────────────────────────────────────────────┘

      必须用英文的：  ,    :    '    "    {  }  [  ]
      不能用中文的：  ，   ：   '    "    ｛ ｝ 【 】

      ⚠️ 这是新手 90% 的报错原因！
      ⚠️ 中文的逗号「，」和英文的逗号「,」看起来很像，但电脑完全不一样。

      【每次打字前，先看一眼输入法是不是英文状态。】
      中文输入法下按 Shift 可以临时切英文。

  ┌────────────────────────────────────────────────────────────────────┐
  │ 铁律二：括号必须成对                                             │
  └────────────────────────────────────────────────────────────────────┘

      每一个 { 都要有一个 } 对应
      每一个 [ 都要有一个 ] 对应

      少一个，整个文件就跑不起来。
      在 VS Code 里，把光标放在一个括号上，它会高亮配对的那个——很好用。

  ┌────────────────────────────────────────────────────────────────────┐
  │ 铁律三：逗号该有的时候要有，不该有的时候别加                       │
  └────────────────────────────────────────────────────────────────────┘

      规则（简化版）：

        · 每一行属性末尾 → 【要】逗号
              title: '关于我',

        · 每一项数组元素末尾 → 【要】逗号
              items: [
                '第一条',
                '第二条',      ← 最后一条也要加，这是允许的
              ],

        · 一个块结束前的最后一项 → 【可以】加，也可以不加
              （建议都加上，省得纠结）

      💡 最省事的做法：【改哪行就在那行末尾加逗号。】
         只要你没删东西，逗号通常不会出问题。

## 【第四章】改完怎么生效？

一、如果你正在跑开发服务器（npm run dev）

  什么都不用做。
  保存文件（Ctrl + S）后，浏览器会**自己刷新**，一秒内就看到新内容。

  💡 这就是 Vite 的"热更新"（HMR）：改代码 → 自动刷新。
     它让你改一行、看一眼，效率极高。

  ⚠️ 但如果浏览器没反应：
     切到那个跑 npm run dev 的黑色窗口，看有没有红色报错。
     通常是标点写错了（见第六章"报错急救"）。

二、如果你要打包给别人看（npm run build）

  改了源文件后，之前打包的 dist 文件夹**不会自动更新**。
  需要重新打包：

      1. 打开终端（在项目文件夹上右键 →「在终端中打开」）
      2. 输入：npm run build
      3. 回车，等十几秒
      4. dist 文件夹就更新了

  ⚠️ 这就是"开发模式"和"打包模式"的区别：
     开发时改完立刻看到；打包后必须重新打包才生效。

  ┌────────────────────────────────────────────────────────────────────┐

      这里是"第一印象"，最重要。建议写：

## 【第六章】报错急救手册

  改完保存后，如果浏览器**白屏了**，或者终端里出现红色报错：

  ┌────────────────────────────────────────────────────────────────────┐
  │ 症状一：终端报错里有 "Unexpected token" 或 "Expected"               │
  └────────────────────────────────────────────────────────────────────┘

      原因：99% 是标点问题。

      检查清单（按顺序排查）：
        □ 是不是用了中文逗号「，」？应该用英文「,」
        □ 是不是用了中文引号「'」「'」？应该用英文「'」
        □ 是不是用了中文冒号「：」？应该用英文「:」
        □ 是不是漏了某个 } 或 ] ？
        □ 是不是漏了某行末尾的逗号？
        □ 是不是误用双引号 " 包住了单引号 ' 里的内容，
           或者单双引号搞混了？——统一用单引号最省事

      💡 最快的排查法：
         看报错信息里的【行号】，跳过去看那一行附近。
         报错说 "line 152" 不一定是 152 行本身错，
         但【一定在附近】（通常是前一行漏了东西）。

  ┌────────────────────────────────────────────────────────────────────┐
  │ 症状二：某幅画挂到了错误的墙上                                       │
  └────────────────────────────────────────────────────────────────────┘

      页面不报错，但那幅画跑到另一面墙去了。

      原因：side 那一项没写对。

      检查：
        □ 一定是 WALL_SIDE.LEFT 或 WALL_SIDE.RIGHT
        □ 大小写完全一致（LEFT / RIGHT 都是大写）
        □ 前面那个 WALL_SIDE. 不能省

      💡 这一项的特性是"【错了也不报错】"，所以只能靠自己核对。
         遇到"画挂错地方了"，第一个就该查它。

  ┌────────────────────────────────────────────────────────────────────┐
  │ 症状三：报错里有 "is not defined"                                  │
  └────────────────────────────────────────────────────────────────────┘

      原因：写了一个程序不认识的名字。

      常见情况：
        · 把 label/value 里的引号漏了：
              { label: 邮箱, value: 'xxx' }
          程序会把"邮箱"当成一个变量名去找，找不到就报
          "邮箱 is not defined"。
          改成 { label: '邮箱', value: 'xxx' } 就好。

        · 把 WALL_SIDE 拼错了（比如 WALLSIDE / WallSide）

  ┌────────────────────────────────────────────────────────────────────┐
  │ 症状四：页面能开，但某幅画的字不见了 / 变成 undefined              │
  └────────────────────────────────────────────────────────────────────┘

      原因：某个属性名打错了，或者少了一个逗号导致两个属性粘在一起。

      解决：把你刚改的那一幅，从上到下对照 3.2 的零件清单挨个检查一遍。

  ┌────────────────────────────────────────────────────────────────────┐
  │ 症状五：改完一切正常，但看不到变化                                  │
  └────────────────────────────────────────────────────────────────────┘

      检查：
        □ 文件真的保存了吗？（记事本标题栏没有 "*" 号）
        □ 改的是不是这个文件？（路径是
           E:\fhgBLOG\IDEAblog\portfolio-3d\src\constants\artworks.js）
        □ 是不是改完 build 过但没重新 build？
        □ 浏览器缓存？按 Ctrl + F5 强制刷新试试

  ┌────────────────────────────────────────────────────────────────────┐
  │ 万能兜底：改坏了怎么办？                                            │
  └────────────────────────────────────────────────────────────────────┘

      最简单的方法：【改之前先备份】。

        1. 在改之前，把 artworks.js 复制一份，
           粘贴在同目录下，改名成 artworks.js.bak
        2. 改坏了，就把 .bak 改回 artworks.js 覆盖回去

      或者，如果你会用 Git：
        git checkout src/constants/artworks.js
      一条命令就还原了。

      💡 养成习惯：【动任何文件之前先备份。】
         这是程序员最重要的自保技能，比任何技巧都实用。

## 【第八章】还想再进一步？（可选）

  如果你改完简历，还想做点更"厉害"的：

  1. 想加第 7 幅画？
     在 CORRIDOR_ARTWORKS 数组里的【最后一个 } 后面加个逗号】，
     然后照着复制一整个 { ... } 块，改掉内容。
     ⚠️ 注意：id 不能和已有的重复。

  2. 想让画挂得更密 / 更疏？
     那要改的是长廊的几何参数，不在这个文件里。
     在 src/ 目录里找和 "corridor" 相关的文件。

  3. 想把程序生成的素描换成真实图片？
     那是另一套改造（涉及贴图加载），
     不在 artworks.js 里改，需要动 src/utils/sketchTextures.js。
     可以单独问一下。

  4. 想改弹窗的字体、间距、颜色？
     在 src/styles/detail.scss 里，
     找 .artwork-detail 相关的样式块。
