## 一、最底层：浏览器是怎么"显示东西"的

### 1.1 什么是网页

| 词 | 通俗解释 | 生活比喻 |
|---|---|---|
| 浏览器 | 一个能"读懂网页说明书"的程序 | 一位能看懂图纸的施工队 |
| HTML | 网页的**内容说明书** | 房子的**结构图**：哪里是墙、哪里是门 |
| CSS | 网页的**外观说明书** | 房子的**装修**：墙刷什么色、门多宽 |
| JavaScript | 网页的**行为说明书** | 房子的**电器**：按开关灯会亮 |
| 渲染 | 浏览器把说明书变成你看到的画面 | 施工队照着图纸把房子盖出来 |

**关键认知**：你把 HTML 文件用记事本打开，看到的是一堆尖括号；用浏览器打开，
看到的是一幅画面。**同一份文件，两种读法。** 浏览器就是那个"翻译官"。

### 1.2 三个最容易搞混的东西

| 词 | 到底是什么 | 比喻 |
|---|---|---|
| `.html` 文件 | 一个**文件**，躺在你硬盘上 | 一张纸质图纸 |
| 网页 | 浏览器**渲染这个文件之后**的画面 | 照着图纸盖好的房子 |
| 网站 | 一堆网页 + 规矩（谁连到谁） | 一个小区 |

### 1.3 `file://` 和 `http://` —— 为什么有时候打不开

这是你会**立刻遇到**的第一个障碍，必须讲清楚。

| 开头 | 含义 | 比喻 | 能做什么 |
|---|---|---|---|
| `file:///E:/.../index.html` | 直接读你硬盘上的文件 | 从自家书架上拿书 | 简单页面都能开；但**不能**用某些高级功能 |
| `http://localhost:5173` | 从"本机上的一个小服务器"取文件 | 小区里有个人专门收发快递 | 功能完整；但**必须先启动那个服务器** |

**为什么 `file://` 会有限制？** 想象你在家里，有些工具是"公共工具"，
必须有个管理员才能借——浏览器出于安全考虑，对 `file://` 打开的页面
关掉了一部分能力（比如某些网络请求、某些模块加载）。

所以你那个 `portfolio-3d` 用 `file://` 直接打开是**打不开的**，
必须先跑 `npm run dev` 起一个小服务器。这不是你操作错了，
是浏览器的安全规则。**这一点想通了，能省掉你未来无数个小时的困惑。**

## 二、HTML —— 网页的骨架

### 2.1 标签：HTML 的"积木"

```html
<h1>我是大标题</h1>
<p>我是一个段落。</p>
<img src="photo.jpg" alt="一张照片">
```

**结构规律**：`<名字 属性="值">内容</名字>`。
比喻：`<名字>` 是"开始包"，`</名字>` 是"结束包"，
中间夹着的东西就装在这个盒子里。属性是贴在盒子外面的标签纸。

### 2.2 你项目里用到的标签

| 标签 | 干什么 | 在你项目里 |
|---|---|---|
| `<html>` | 整个文件的容器 | 每个页面都有 |
| `<head>` | 放"给浏览器看的"信息（不显示出来） | 标题、样式表、字体 |
| `<body>` | 放"给用户看的"内容 | 页面正文 |
| `<div>` | 万能盒子，用来分组 | 到处都是 |
| `<a href="...">` | 链接 | 导航栏、按钮 |
| `<canvas>` | **一块画布**（3D 就画在这里） | `#idea-gl` |
| `<header>` / `<nav>` / `<main>` | 语义化盒子（和 div 一样，但名字有意义） | 顶部导航 |
| `<meta>` | 元信息 | `charset="UTF-8"`（字符编码） |

### 2.3 三个必须理解的细节

**① `charset="UTF-8"` 为什么必须有**

计算机存中文时，要用一套"编码规则"。UTF-8 是国际通用的那套。
不写这行，浏览器可能按别的规则去猜，中文就变成"锟斤拷"这种乱码。
比喻：你和对方约好用普通话，结果对方以为你说方言，就听岔了。

**② `<a href="...">` 的 href 写什么**

| 写法 | 意思 | 你项目里的例子 |
|---|---|---|
| `href="ideas.html"` | 同目录下的另一个文件 | 导航栏「想法集」 |
| `href="http://localhost:5173"` | 一个完整网址 | 「3D 长廊」入口 |
| `href="#top"` | 跳到本页某个位置 | 锚点 |
| `href="file:///E:/..."` | 明确指定硬盘路径 | 3D 页面返回首页的链接 |

**⚠️ 关键规则**：跨"协议"（`file://` ↔ `http://`）**必须写完整网址**。
写 `/portfolio-3d/` 或 `../portfolio-3d/` 会被理解成"硬盘上的某个位置"，
然后找不到，报 404。**你之前那个"找不到文件"就是这么来的。**

**③ `<canvas>` 是什么**

一块**没有内容**的画布。HTML 只负责"占个位置、给个尺寸"，
里面的东西全靠 JavaScript 一笔一笔画上去。3D 就是往这块画布上画。

## 三、CSS —— 网页的外观

### 3.1 CSS 的写法：选谁 + 改成什么

```css
.idea-brand {
  color: white;
  font-size: 20px;
}
```

读法：**"选中所有 `class="idea-brand"` 的元素，把文字改成白色、字号 20 像素。"**

比喻：CSS 是一份"装修指令清单"，每条指令都是
「**哪间房** → **做什么**」。

### 3.2 三种"选谁"的方式

| 写法 | 名字 | 比喻 | 例 |
|---|---|---|---|
| `p` | 标签选择器 | "所有的门" | `h1 { }` 所有大标题 |
| `.name` | 类选择器 | "所有贴着'蓝色'标签的门" | `.idea-brand { }` |
| `#name` | ID 选择器 | "身份证号是 X 的那扇门" | `#idea-dive-end { }` |

**优先级**：ID > 类 > 标签。就像"叫张三"比"所有戴帽子的"更精确。

### 3.3 布局：把东西放到该在的位置

这是 CSS 最难的部分，但只有两个核心概念：

**① 盒子模型（Box Model）**

每个元素都是一个矩形盒子，从里到外四层：

```
┌─────────── margin（外边距，推开别的盒子）
│ ┌───────── border（边框）
│ │ ┌─────── padding（内边距，撑开自己）
│ │ │ ┌───── content（内容，文字/图片）
│ │ │ │
│ │ │ └─────
│ │ └───────
│ └─────────
└───────────
```

比喻：**快递盒**。content 是货，padding 是气泡膜，
border 是纸盒本身，margin 是盒子和盒子之间的空隙。

**② `position`：元素怎么定位**

| 值 | 含义 | 比喻 |
|---|---|---|
| `static` | 默认，跟着排版流走 | 排队的人，别人动我也动 |
| `relative` | 相对原位微调 | 排队时往前挪半步 |
| `absolute` | 相对最近的"定位祖先"摆放 | 贴在墙上，跟队伍无关 |
| `fixed` | 相对**屏幕**摆放，滚动不动 | 贴在窗户上的贴纸 |

**🔥 这里有个你项目里真实踩过的坑（务必记住）**：

`position: fixed` 的元素，如果**同时**给了 `top` 和 `bottom`，
它会**纵向拉满整个屏幕**——因为浏览器理解成
"上面离屏幕 20px，下面离屏幕 20px，中间的全给它"。

你项目里的操作提示 `.boot-badge` 和返回链接 `.back-home`
都吃过这个亏：本意是"在右下角显示一个小提示"，
结果变成"一块铺满右半屏的色板"。

**口诀**：`fixed` 元素，`top` 和 `bottom` **只给一个**；
`left` 和 `right` **只给一个**；再补一句 `height: auto` 保平安。

### 3.4 `z-index`：谁盖在谁上面

数字越大越靠前。比喻：**桌上的纸**，z-index 是"离你眼睛的远近"。

你项目里的层级：3D 画布（0） → 操作提示（UI 层） → 弹窗（更高）。

## 四、JavaScript —— 网页的行为

### 4.1 从"变量"和"函数"开始

```js
let name = "小明";          // 变量：一个贴了标签的盒子，里面装着东西
function sayHi(who) {        // 函数：一台机器，喂进去东西，吐出来东西
  return "你好，" + who;
}
sayHi("小明");               // 使用（调用）这台机器
```

| 词 | 通俗解释 | 比喻 |
|---|---|---|
| 变量 | 一个能装东西的盒子，贴了名字 | 冰箱里标着"鸡蛋"的那格 |
| 函数 | 一段"可以做某件事"的代码，可以反复用 | 一台豆浆机：放豆子，出豆浆 |
| 参数 | 喂给函数的东西 | 放进豆浆机的豆子 |
| 返回值 | 函数吐出来的东西 | 豆浆机出来的豆浆 |
| `if` | 如果……就…… | 岔路口看红绿灯 |
| `for` | 重复做 N 次 | 洗 5 个碗 |

### 4.2 「对象」—— JS 里最重要的概念

```js
const person = {
  name: "小明",
  age: 18,
  sayHi: function() { return "嗨"; }
};
person.name;    // 取值："小明"
person.sayHi(); // 用它的功能
```

比喻：**一个抽屉柜**。`person` 是柜子，`name` / `age` 是抽屉的标签，
`person.name` 是"打开 person 柜子里标着 name 的那个抽屉"。

**为什么重要**：Three.js 里的一切都是对象。
`scene`（场景）是个对象，`camera`（相机）是个对象，
`mesh`（物体）也是个对象。理解了对象，你就理解了 3D 库的用法。

### 4.3 事件 —— "用户做了什么，我要响应"

```js
button.addEventListener("click", function() {
  console.log("你点了我！");
});
```

读法：**"给 button 装一个监听器：一旦有人点它，就执行这段代码。"**

常见事件：

| 事件名 | 什么时候触发 |
|---|---|
| `click` | 点一下 |
| `mousemove` | 鼠标移动 |
| `mouseover` | 鼠标移进去（悬停） |
| `scroll` | 滚动 |
| `keydown` | 按下键盘 |

**你项目里的 hover 上色、点击弹窗、滚动下潜，全部是事件。**

### 4.4 异步：为什么代码不按顺序执行

```js
console.log("A");
setTimeout(() => console.log("C"), 1000);  // 1 秒后才做
console.log("B");
// 实际输出：A → B → C
```

**为什么？** 因为浏览器**不会为了等 1 秒就卡住不动**。
它先把能做的做完（A、B），1 秒后再回来做 C。

比喻：**点外卖**。你下单后不会站在门口干等，
而是继续做别的事，等外卖到了再开门。

**这个词叫「异步」。** 你项目里加载贴图、加载字体、等 3D 首帧，
全是异步操作——所以能看到 `async`、`await`、`Promise` 这些词。

## 五、Three.js —— 在网页里画 3D

### 5.1 拍电影的比喻（这是理解 Three.js 的钥匙）

用 Three.js 画 3D，就像**拍一场电影**：

| Three.js 概念 | 电影里的对应物 | 作用 |
|---|---|---|
| `Scene` 场景 | 整个片场 | 装所有东西的容器 |
| `Camera` 相机 | 摄影机 | 决定"从哪里看" |
| `Mesh` 网格物体 | 演员/道具 | 能被看到的实体 |
| `Geometry` 几何体 | 道具的形状 | 立方体？球？平面？ |
| `Material` 材质 | 道具的表面质感 | 木头？金属？纸？ |
| `Light` 光源 | 灯光师 | 有光才有明暗 |
| `Renderer` 渲染器 | 摄影师 + 冲洗 | 把"看到的东西"变成像素 |

**最小可运行例子**（这就是 3D 的"Hello World"）：

```js
// 1. 建片场
const scene = new THREE.Scene();

// 2. 摆摄影机（视角 75 度，宽高比，近处最远能看多近，远处最远能看多远）
const camera = new THREE.PerspectiveCamera(75, width / height, 0.1, 1000);
camera.position.z = 5;   // 把摄影机往后拉 5 米

// 3. 造道具：一个立方体
const geometry = new THREE.BoxGeometry(1, 1, 1);          // 形状
const material = new THREE.MeshBasicMaterial({ color: 0x44aa88 }); // 材质
const cube = new THREE.Mesh(geometry, material);           // 合体！
scene.add(cube);                                           // 放进片场

// 4. 请摄影师
const renderer = new THREE.WebGLRenderer();
renderer.setSize(width, height);
document.body.appendChild(renderer.domElement);   // 把画布插进页面

// 5. 开拍（每帧画一次，才能动起来）
function animate() {
  cube.rotation.x += 0.01;    // 让它转起来
  cube.rotation.y += 0.01;
  renderer.render(scene, camera);
}
renderer.setAnimationLoop(animate);   // 每秒约 60 次
```

### 5.2 「渲染循环」—— 3D 动起来的心跳

上面那个 `animate` 函数，浏览器**每秒会调用它大约 60 次**。

比喻：**翻页动画**。你在书的每一页画一个稍微不同的姿势，
快速翻动看起来就像在动。3D 就是这么"动"的——
每 1/60 秒重画一次整个画面。

**这解释了一件重要的事**：为什么 3D 页面会"卡"。
如果每次重画要花的时间超过 1/60 秒（16.7 毫秒），
就会掉帧，看起来一顿一顿的。

### 5.3 坐标系：3D 空间里的"地址"

Three.js 用三个数字定位：`(x, y, z)`

```
        y（向上）
        ↑
        │
        │
        └────────→ x（向右）
       ╱
      ╱
     z（向屏幕外，朝你）
```

比喻：**在一栋楼里找一个房间**——x 是"第几列"，y 是"第几层"，z 是"第几进"。

**记忆技巧**：
- `x` 变大 → 往右移
- `y` 变大 → 往上移
- `z` 变大 → 往你这边移（离你更近）

### 5.4 相机：两种视角

| 类型 | 效果 | 比喻 | 用途 |
|---|---|---|---|
| `PerspectiveCamera` 透视相机 | 近大远小 | 人眼、手机镜头 | 99% 的场景 |
| `OrthographicCamera` 正交相机 | 远近一样大 | 工程制图 | 2D 界面 |

你项目里的"长廊"用的是透视相机——所以走廊远处的画框看起来小。

### 5.5 材质：为什么有的东西亮、有的东西暗

| 材质 | 特点 | 比喻 |
|---|---|---|
| `MeshBasicMaterial` 基础材质 | **不受光照影响**，永远是这个颜色 | 贴了自发光贴纸的板子 |
| `MeshStandardMaterial` 标准材质 | 受光照影响，能表现金属/粗糙 | 真实的铁皮、木料 |
| `MeshLambertMaterial` | 受光但计算简单（便宜） | 涂了哑光漆 |
| `ShaderMaterial` 着色器材质 | 你自己写代码决定每个像素 | 完全自制滤镜 |

**🔥 你项目里有个关键选择**：素描长廊用的是 **`MeshBasicMaterial`（不受光）**，
而且把全局光照注释掉了。为什么？因为那种美术风格要的是
"纸上的墨线"——**纯平、不受光照影响**，就像真的白纸黑线。
如果加了光照，墙会有明暗渐变，反而不像纸了。

**这告诉你一件事：技术选择要服从美术目标，不是越"高级"越好。**

### 5.6 Texture 贴图：给物体"贴皮"

```js
const loader = new THREE.TextureLoader();
const texture = loader.load("drawing.png");
const material = new THREE.MeshBasicMaterial({ map: texture });
```

比喻：**给手机贴膜**。几何体是手机的形状，`map` 是那层膜的花纹。

你项目里每个画框都有两张贴图：
- `sketchMap` 素描版（黑白）
- `paintedMap` 彩色版
两者之间用着色器做"擦除式切换"。

### 5.7 为什么你的项目有「无限长廊」却不会越来越卡

这是个**聪明的技巧**，值得单独理解。

如果走廊真的是一条无限长的实体，那内存会被撑爆。
实际做法是：**只造 4 段走廊，然后在相机跑远时"搬回来"重排**。

比喻：**跑步机**。你一直在跑，但跑步机只有那么长——
跑到头的时候，它把传送带循环了，你感觉像在无限跑。

关键词：**对象池 / 循环复用（pooling / recycling）**。

## 六、GLSL 着色器 —— 决定"每个像素什么颜色"

### 6.1 着色器是什么

普通 JS 是在"CPU 上、一次处理一件事"。
着色器是在**显卡上、同时处理几百万个像素**。

比喻：
- **CPU（普通 JS）** = 一个很聪明的教授，一次算一道很复杂的题
- **GPU（着色器）** = 一万个小学生，同时算一万道很简单的题

因为屏幕上有一两百万个像素，每个像素都要算颜色——
用"一万个小学生"才对。

### 6.2 两种着色器

| 名字 | 管什么 | 比喻 |
|---|---|---|
| 顶点着色器 Vertex Shader | 每个**顶点**的位置 | 决定木偶的关节在哪 |
| 片元着色器 Fragment Shader | 每个**像素**的颜色 | 决定每个关节涂什么颜色 |

### 6.3 最小例子：让颜色随位置变化

```glsl
// 片元着色器的核心思路
void main() {
  vec2 uv = vUv;                 // uv 是"这个像素在贴图上的位置"，范围 0~1
  gl_FragColor = vec4(uv.x, uv.y, 0.5, 1.0);  // 红=横坐标，绿=纵坐标
}
```

效果：左下角黑、右上角黄绿，中间渐变。

### 6.4 你项目里那个"素描上色"是怎么做到的

核心思路分四步：

```
① 算出这个像素在"世界"里的位置   → 世界坐标
② 减掉画框自己的位置             → 得到"相对画框"的坐标
③ 沿一个方向投影，得到一个距离     → 这个像素"在刷子的左边还是右边"
④ 和一个"阈值"比较
     距离 < 阈值  → 显示彩色贴图
     距离 > 阈值  → 保持素描
   阈值随进度从很小变到很大 → 就有了"刷过去"的效果
```

**为什么要加噪声？** 如果阈值是一个固定数字，边界会是一条**笔直的线**，
看起来像拿尺子比着擦的，很假。
加一点随机扰动，边界就变成**锯齿状、像真的笔刷**。

比喻：**撕纸 vs 切纸**。切纸是直边，撕纸是毛边。
噪声就是那个"毛边生成器"。

### 6.5 `onBeforeCompile` —— 在别人的程序里"插一段"

Three.js 内置的材质已经写好了完整的着色器。
你不可能整个重写，但你可以在**中间的某个位置插一段自己的代码**。

```js
material.onBeforeCompile = (shader) => {
  // shader.fragmentShader 是一段"字符串"形式的 GLSL 代码
  shader.fragmentShader = shader.fragmentShader.replace(
    '#include <map_fragment>',      // 找到这个"锚点"
    '#include <map_fragment>' + `
      // ...插在这里的代码
    `
  );
};
```

比喻：**在一篇文章的某个段落后面，粘贴一段补充说明**。
锚点就是"我要插在这句话之后"。

**🔥 这里有个你项目里踩过的、极其隐蔽的坑（必看）**

上面那段插进去的代码写在 **JavaScript 的模板字符串**（反引号包围）里。
而**反引号会结束模板字符串**！

你在 GLSL 注释里为了排版写了一句：

```js
//   第一版写成 `(1.0 - smoothstep(...))`，     ← 这两个反引号！
```

结果：模板字符串在这里**提前结束**了，后面的
`smoothstep(...)` 变成了 JavaScript 代码，浏览器报
`ReferenceError: smoothstep is not defined`。

**最坑的是**：`npm run build` 完全不报错（构建 611 个模块全绿），
只有真正在浏览器里跑才炸。

**教训两条**（都是通用的）：
1. 往模板字符串里塞代码时，**注释里也不要出现反引号**。
2. **"构建通过"不等于"能跑"**——必须真的打开浏览器看。

## 七、React —— 把界面拆成"零件"

### 7.1 为什么需要 React

假设你要做一个按钮，点一下数字 +1。

**不用 React**：你得手动找到显示数字的那个元素，改它的文字。

```js
document.getElementById("count").textContent = count;
```

**用 React**：你只描述"数字是多少"，界面自己更新。

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

比喻：
- **不用 React** = **手动挡**：你自己去拧齿轮换挡
- **用 React** = **自动挡**：你只说"我要加速"，变速箱自己去配合

### 7.2 组件：像搭乐高

```jsx
function Header() {
  return <h1>我的网站</h1>;
}

function App() {
  return (
    <div>
      <Header />        {/* 把 Header 当成一个积木块用 */}
      <p>正文</p>
    </div>
  );
}
```

比喻：**自定义积木**。官方给了方块、圆块，
你把几个拼起来做成一个"车头"，之后就能反复用这个"车头"。

**你项目里的组件**：
`Scene`（整个 3D 场景）、`CorridorSegment`（一段走廊）、
`PictureFrame`（一个画框）、`ArtworkDetail`（详情弹窗）……

### 7.3 `props`：给组件"传参数"

```jsx
function Greeting({ name }) {      // 接收参数
  return <p>你好，{name}</p>;
}

<Greeting name="小明" />           // 传进去
```

比喻：**点菜**。`Greeting` 是"做一道菜的流程"，
`name="小明"` 是"这道菜要加小明"。同一个流程，加不同料，出不同菜。

你项目里：`<PictureFrame artwork={artwork} side="left" />`
——同一个画框组件，传入不同的作品数据，渲染出不同的画。

### 7.4 `state`：组件"记住的东西"

```jsx
const [count, setCount] = useState(0);
//    ↑当前值   ↑改它的方法      ↑初始值
```

读法：**"count 这个记忆格，初始是 0；要改它必须用 setCount。"**

**⚠️ 铁律：不能直接改，必须用 `setCount`。**

```js
count = count + 1;        // ❌ 界面不会更新（React 不知道你改了）
setCount(count + 1);      // ✅ React 知道要重新渲染
```

比喻：state 是**白板上的字**。
你偷偷把字改了但没告诉别人，别人看不到；
你得通过"广播"（`setCount`）让所有人都知道。

### 7.5 「重新渲染」—— React 的核心机制

当 state 变了，React 会**重新执行你的组件函数**，
算出新的界面应该长什么样，然后只把**变化的部分**更新到页面上。

比喻：**微信聊天记录**。新消息来了，不会重画整个屏幕，
只把新气泡加到底部。React 做的就是这个"只改该改的"。

### 7.6 `useEffect`：做"副作用"

有些事不该在"渲染"时做，比如：发网络请求、订阅事件、启动动画。
这些叫"副作用"，放在 `useEffect` 里。

```jsx
useEffect(() => {
  console.log("组件出现了");
  return () => console.log("组件要消失了");   // 清理函数
}, []);   // ← 这个数组叫"依赖"，空数组 = 只执行一次
```

比喻：**入住和退房**。`useEffect` 是"入住时要做什么"，
返回的函数是"退房时要做什么"（关灯、关水龙头）。

**你项目里的用法**：组件挂载时把调试桥挂到 `window` 上，
卸载时删掉它。

### 7.7 React Three Fiber（R3F）—— 用 React 的方式写 Three.js

这是你项目的关键技术。它让 Three.js 的每个概念变成一个"组件"。

```jsx
// 纯 Three.js 写法
const geometry = new THREE.BoxGeometry(1, 1, 1);
const material = new THREE.MeshBasicMaterial({ color: "red" });
const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);

// R3F 写法（一模一样的效果，只是"声明式"）
<mesh>
  <boxGeometry args={[1, 1, 1]} />
  <meshBasicMaterial color="red" />
</mesh>
```

**规律**：Three.js 里的 `new XXX()`，在 R3F 里就是 `<xxxXXX />`（首字母小写）。

| Three.js | R3F |
|---|---|
| `new THREE.Mesh()` | `<mesh>` |
| `new THREE.BoxGeometry()` | `<boxGeometry>` |
| `new THREE.MeshBasicMaterial()` | `<meshBasicMaterial>` |
| `scene.add(x)` | 写在 `<Canvas>` 里面就行 |

比喻：**宜家家具**。
- 纯 Three.js = 你拿螺丝刀一个个装
- R3F = 说明书上画好了"这块插那块"，你照着摆

### 7.8 `useFrame`：R3F 的渲染循环

```jsx
useFrame((state, delta) => {
  meshRef.current.rotation.y += delta;   // 每帧转一点
});
```

相当于前面讲的 `animate` 函数，但更省事——R3F 帮你接好了循环。

**🔥 这里有个非常重要的坑（你项目里真踩过）**

`useFrame` 每帧都在写某个值（比如 `progress`）。
如果你在别的地方（比如测试脚本）也去写同一个值，
**你写的会在 16 毫秒内被 `useFrame` 覆盖掉**，
表现为"我明明设了值，却完全没反应"。

**原则：一个数据只能有一个"写入者"。**
如果外部需要控制它，代码里必须**专门开一个口子**
（比如提供 `freezeAll()` 方法），而不是去直接改底层变量。

## 八、npm 和 Vite —— 开发者的"省力工具"

### 8.1 npm：代码的"应用商店"

```bash
npm install three        # 下载 three.js 这个库到你的项目里
npm run dev              # 运行 package.json 里定义的 "dev" 脚本
```

比喻：**点外卖**。
`package.json` 是购物清单，`node_modules` 是收到的食材堆，
`npm install` 是下单动作。

| 名词 | 是什么 |
|---|---|
| `node_modules/` | 下载来的所有代码库（**很大，不要手改**） |
| `package.json` | 项目说明书：我叫什么、依赖什么、怎么启动 |
| `package-lock.json` | 精确版本的锁定记录（保证换台电脑装出来一样） |
| `npm` | 那个"点外卖"的命令行工具 |

### 8.2 Vite：自动编译 + 自动刷新

**它解决什么问题？**

现代前端代码浏览器**不能直接运行**，因为：
- 你写 `.jsx`（React 的语法），浏览器不认识
- 你 `import` 别的文件，浏览器对 `file://` 有限制
- 你写最新语法，老浏览器不支持

Vite 就是**翻译 + 打包 + 实时刷新**的工具。

比喻：**同声传译**。
你说中文（JSX/新语法），Vite 立刻翻译成听众能懂的英文（浏览器能跑的 JS），
而且你每改一句，翻译立刻更新——不用重新开场。

| 命令 | 干什么 | 什么时候用 |
|---|---|---|
| `npm run dev` | 启动开发服务器，改代码自动刷新 | **开发时**（你日常用这个） |
| `npm run build` | 编译成"最终成品"，放进 `dist/` | 准备发布时 |
| `npm run preview` | 预览 `dist/` 里的成品 | 发布前检查 |

### 8.3 `import` / `export`：模块化

```js
// utils.js
export function add(a, b) { return a + b; }

// main.js
import { add } from './utils.js';
add(1, 2);
```

比喻：**工具箱**。`export` 是"把工具放进公共工具箱"，
`import` 是"从工具箱里拿工具出来用"。

好处：代码可以拆成很多小文件，各管一件事，而不是一个文件一万行。

### 8.4 「热更新」HMR：为什么改代码不用刷新

HMR = Hot Module Replacement（热模块替换）。

修改一个文件时，Vite 只把**这个文件**重新加载，
保持页面其他状态不变。

比喻：**换轮胎不用换整辆车**。
改一个组件，页面不刷新，你正在看的位置、输入的内容都还在。

## 九、调试 —— 出问题了怎么找原因

### 9.1 浏览器开发者工具（F12）

**按 F12 打开**。这是你未来最重要的工具，没有之一。

| 面板 | 看什么 | 什么时候用 |
|---|---|---|
| **Console** 控制台 | 报错信息、`console.log` 输出 | **第一个要看的地方** |
| **Elements** 元素 | 页面的 HTML 结构和 CSS | 排版不对、样式没生效 |
| **Network** 网络 | 每个文件的加载情况、状态码 | 图片不显示、404 |
| **Sources** 源代码 | 打断点、单步执行 | 逻辑不对，想知道哪一步错了 |
| **Application** 应用 | 本地存储、Cookie | 数据没存住 |

**读报错的方法**（这个技能比什么都重要）：

```
Uncaught ReferenceError: smoothstep is not defined
    at material.onBeforeCompile (paintRevealMaterial.js:209:17)
         ↑ 谁在报错                    ↑ 文件和行号：列号
```

读法：
1. **第一行**告诉你"错在哪类问题"——这里是"用了一个没定义的叫 smoothstep 的东西"
2. **第二行**告诉你"哪里出的错"——`paintRevealMaterial.js` 第 209 行
3. **点那个文件和行号**，会跳到源码对应位置

比喻：报错信息是**医院的检验报告**。
第一行是"诊断结论"，后面是"哪项指标异常"。
不要被吓到，只要会读前两行，80% 的问题能自己解决。

### 9.2 常见报错速查

| 报错 | 意思 | 通常怎么修 |
|---|---|---|
| `XXX is not defined` | 用了个没定义的东西 | 拼写错了？忘了 import？ |
| `Cannot read properties of undefined` | 想读一个不存在的东西的属性 | 那个东西还没准备好（异步！） |
| `404 Not Found` | 文件找不到 | 路径写错了 |
| `CORS error` | 跨域被拦 | 需要用服务器打开，别用 `file://` |
| `Failed to load module script` | 模块加载失败 | 检查路径、检查有没有起服务器 |
| `THREE is not defined` | three.js 没加载成功 | 脚本标签顺序错了？路径错了？ |

### 9.3 我（你的助教）用的高级武器：自动化验证

做你这两个项目时，我用了一套**自动化测试**的方法：
写一个脚本，控制真实浏览器去点、去悬停、去截图、去数像素。

**为什么需要它？** 因为我发现了一个残酷的事实：

> **`npm run build` 全绿，页面照样可能是坏的。**

比如那个 `smoothstep` 的错误，构建时 611 个模块全部编译通过、
零警告；只有真的在浏览器打开，才报错。

比喻：**体检 vs 实际跑步**。
体检报告全正常（构建通过），不代表你能跑马拉松（真的能用）。

**你的项目现在都有自动化验证脚本**，都在
`E:\fhgBLOG\IDEAblog\.ref\` 里。跑法：

```bash
cd E:\fhgBLOG\IDEAblog\.ref
node link-check.mjs      # 检查两个页面之间的链接
node site-check.mjs      # 检查首页能不能正常显示
```

### 9.4 调试的心法（十年经验总结）

1. **不要一次改很多地方。** 改一处，验证一处。一次改五处，出了问题你不知道是哪个引起的。
2. **善用 `console.log`。** 想知道某个变量是不是你以为的值？打印出来。**不要猜。**
3. **报错先读，别急着搜。** 80% 的报错第一行就说清了原因。
4. **二分法定位。** 代码很多不知道哪错？注释掉一半，看还错不错，逐次缩小范围。
5. **小黄鸭调试法。** 把代码一行行念给（一个玩具鸭/同事/空气）听，念到某行你往往自己就发现了。
6. **"昨天还能跑"要先看改了什么。** 用 Git 看改动（见下）。
7. **Ctrl+Z 是你的朋友，Git 更是。** 改坏了要能回去。

## 十三、遇到问题怎么办（求助的正确姿势）

### 13.1 搜索关键词的写法

**❌ 不好的搜法**：
> 我的网页坏了怎么办

**✅ 好的搜法**（把报错原文贴上去）：
> `ReferenceError: smoothstep is not defined` onBeforeCompile three.js

**规则**：
1. **报错原文照贴**（去掉你自己的文件名和路径）
2. **加上技术名**（three.js / react / vite）
3. **英文搜法往往结果更好**（技术问题英文资源多）
4. 加上版本号更精确：`three.js r182`

### 13.2 去哪问

| 地方 | 特点 |
|---|---|
| 官方文档 | **最先看这里**，最准 |
| MDN | Web 技术的事实标准，中文齐全 |
| Stack Overflow | 英文问答，问题几乎都被问过 |
| GitHub Issues | 库的官方 bug 区，搜有没有人遇到同样问题 |
| 掘金 / 思否 | 中文技术社区 |
| B站 | 看视频教程（见下一份《学习资源地图》） |

### 13.3 我的建议：先自己试 15 分钟

遇到问题的**正确顺序**：

1. **读报错**（2 分钟）—— 80% 的情况这里就解决了
2. **`console.log` 看真实值**（3 分钟）—— 别猜
3. **搜索**（5 分钟）—— 贴报错原文
4. **看官方文档**（5 分钟）—— 特别是"参数是什么意思"
5. **实在不行再问人** —— 但问的时候把你**试过的**都说清楚

**为什么强调"先自己试"？**
因为**自己找到答案的过程，才是真正在学**。
直接问到的答案，下次遇到还是不会。

但也不要死磕——**卡住超过 1 小时就该求助**，
死磕会消磨兴趣。这个度要自己把握。
